# Доступ к Бухэксперт8 (buhexpert8.ru)

Сайт — WordPress, и его штатный REST API (`/wp-json/wp/v2/...`) открыт
анонимно: индекс `/wp-json` при этом отключён (404), но сами точки отвечают.
Альтернативный вход в REST — `/?rest_route=/wp/v2/...` (тоже работает).

## Точки, которые использует сервер

| Точка | Назначение |
|---|---|
| `GET /wp-json/wp/v2/search?search=...&per_page=N&type=post&subtype=post` | Поиск: id, title, url найденных постов |
| `GET /wp-json/wp/v2/posts/{id}` | Пост: title.rendered, link, content.rendered |
| `GET /wp-json/wp/v2/posts?slug={slug}` | Тот же пост по slug (последний сегмент URL без `.html`) |
| `POST /wp-login.php` | Вход подписчика (только когда задан файл buhexpert_credentials.txt) |

## Что важно знать про контент

- **Открытые материалы** — в `content.rendered` лежит полный HTML;
  сервер конвертирует его в Markdown (trafilatura, как и для ИТС).
- **Платные материалы** — в `content.rendered` вместо текста заглушка:
  `<div class="noaccess-block">…«оформите коммерческую подписку»…`.
  Сервер детектит `noaccess-block` и не выдаёт текст заглушки как материал:
  анонимно — сообщение «материал платный», у подписчика — полный текст
  с HTML-страницы.
- **Вопросы-ответы** — анонимно в REST приходит только текст вопроса
  (сотни байт); ответ эксперта платный, в REST его нет.
- **HTML-страница и REST анонимно дают одно и то же**: на странице платного
  материала та же заглушка, «лишнего» текста нет (проверено в сентябре 2026).
  Поэтому анонимный `buhexpert_get` читает только REST, а HTML-страницу
  тянет лишь подписчик: платная часть и ответы на вопросы отдаются только
  там, с куками сессии.

## Вход подписчика

WordPress обрабатывает `POST /wp-login.php` с полями `log`, `pwd`,
`wp-submit`, `redirect_to`, `testcookie=1`; обязательна кука
`wordpress_test_cookie=WP Cookie check`. Успех — по появлению куки
`wordpress_logged_in_*` в общем хранилище httpx-клиента. Неверный логин
возвращает 200 с `div#login_error` (например, «Неизвестный адрес email…») —
сервер вставляет этот текст в примечание `its_status` и дальше работает
анонимно; повторных попыток входа в процессе не делает.

Ограничения: если сайт поставит капчу на вход, сменит форму на кастомную
или закроет REST API — править `_be_ensure_session()` / `be_get_raw()` /
`be_search_raw()` в `src/mcp_1c_its/server.py`. Троттлинг и кэш общие с
остальными ресурсами: пауза ≥1 с между запросами, материалы — неделя,
поиск — сутки.

## Проверка

`python -m mcp_1c_its.check` печатает блок `buhexpert8.ru`: источник учётных
данных, результат поиска, заголовок материала и состояние входа (если
учётная запись задана).
